One petal per top-level branch, each shaped by that branch's own AHU subtree hash — so the petal that moves is the branch that changed, and an amber petal is a subtree that differs from the confirmed tree. Teal is what you see, violet what the server has confirmed; a petal tinted toward someone's colour was last written by them. One figure at rest.
Algorithms at work
AHU / Merkle treeO(log n)
rooted labelled tree · bottom-up hash fold
Each node's hash folds its children's, in order. Comparing two trees for the first differing subtree costs one descent, not a leaf-by-leaf walk.
Causal latticeO(V+E)
partial order · concurrency + longest chain
Edges are basedOn. Anything with no causal path either way is flagged concurrent — genuinely simultaneous edits, which is exactly what more editors produce more of.
LSM-style op logO(log n)
memtable → levels · compaction on age
The server's log, stored the way an LSM engine would: a small hot buffer flushing into progressively larger, immutable levels that compact as they fill.
Operational transformO(1) / pair
xform(a, b) · all 4 op kinds × each other
Concurrent block inserts after the same sibling order by site id; a text op inside a block someone else removed is annihilated.

Re-checked every frame against live state, not asserted. The third and fourth are different instruments — turn off rebase and only one of them goes amber. The fifth replays the sequencer's log from empty and compares it to the confirmed view this client assembled incrementally over a lossy wire — the two are built by different code, which is the only reason comparing them means anything.
Pending queue —
One op is on the wire at a time. The rest wait here and are transformed in place while they wait — basedOn only names a well-formed context if its author has nothing else outstanding.
