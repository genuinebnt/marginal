Block structure
The editor never mutates the block tree directly…unchanged
↑Positions are anchors, never integer offsets…MoveBlock { from: 4, to: 2 }
A markdown document is parsed on every render…InsertText, DeleteText
Callout — a block kind, not a style…InsertBlock { kind: callout }
TODO: decide whether spans are stable…DeleteBlock { tombstone }
The moved block is the point. A flat text diff sees the third paragraph vanish and reappear — a delete plus an insert, and the reader has to work out they are the same words. The op log already knows it was a move, because MoveBlock carries from as well as to so that it can be inverted. The diff is a rendering of what the ops say, not a reconstruction of what might have happened.
LCS table — every cell computed, traceback outlined
This is the algorithm, not a picture of it. Each cell is max(up, left), or diagonal + 1 where the tokens match — those are the teal cells. The outlined path is the traceback that becomes the edit script.

It is also the argument against using it: the table is O(n·m) cells. Fine for the sentence above, ruinous for a document, which is why Myers walks the same edit graph in O(nd) where d is the number of differences — small whenever two revisions are actually similar, which consecutive revisions always are.
