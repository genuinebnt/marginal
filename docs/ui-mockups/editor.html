Collaborative editing spec

Edited by you and Ada · 3 collaborators today

The editor never mutates the block tree directly. Every keystroke, paste, and drag compiles to an Op, which is applied locally for instant echo and appended to the log for durability and sync.

◌

Positions are anchors, never integer offsets — see [[Anchors vs offsets]] for why a concurrent remote edit invalidates an offset but not an anchor.

Type ## at the start of this line to watch the input rule fire.

Why a block tree, not text

A markdown document is parsed on every render, so two people editing it must reconcile text. A block tree is parsed once at input time, so two people editing it apply ops to nodes. That is the whole reason live collaboration works here and merge-conflict UI never appears.

◆
Callout — a block kind, not a style. Converting a paragraph to this emits SetBlockKind{from, to}, which carries from so it inverts.

The representation boundary

enum Op {
    InsertText  { block: BlockId, at: Anchor, text: String },
    DeleteText  { block: BlockId, range: AnchorRange, text: String },
    SetBlockKind{ id: BlockId, from: BlockKind, to: BlockKind },
}

spans is storage; rope + anchored marks is the working format. Exactly one conversion site each way.

◌

Toggle blocks

Collapse state is view state, not model state

If it were stored on the block, collapsing a toggle would be a collaborative edit — everyone else's screen would move when you tidied yours.
